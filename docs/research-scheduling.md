# Research-only 调度升级

基线：`bd86692c81838739b54a297a7643558037936f3c`。Skill 包标识：`meme-studio-v3.1.2-research-only`。

## 范围

只修改机制研究的调度、阶段指令、研究 Skill、版本清单和测试。新增 `lib/research-state.mjs` 承担合并与预算状态逻辑。

不修改 `server.mjs`、`public/`、部署配置、环境变量、依赖版本、素材提取脚本、分析 schema 或改编 schema；不加入 MVCE、内容导入、远程访问或 Cloudflare。保留当前梗理解入口和改编 Skill 3.1 的原文件。

`vendor/manifest.json` 按实际 15 个 Skill 文件重新计算哈希，并修正基线中未跟随改编 Skill 3.1 更新的版本/哈希。现有服务器和页面里的旧改编版本标签不在本次修改范围内。

## 行为变化

1. 同一机制 ID 可以更新，而不是只做去重。事实发生变化时，要求来源 URL、具体支持内容或证据类型有更新；保存修正前、提议版本和采纳决定。无更新依据的冲突保留原记录并阻止自动完成。字段顺序变化不会被误判为事实变化。此检查不能自动证明来源真实性。
2. `run.researchProgress` 独立保存轮次、总预算、累计执行时间、当前尝试、历史修正和冲突。失败/取消后的重试从最后提交的完整轮次继续，不因存在部分 `research` 就直接改编，不重置预算。
3. 默认最多三轮、共享 300,000 毫秒执行预算。每轮在获得执行槽位后，按剩余预算/剩余轮次分配；未消耗时间滚入后续轮次。只从 CLI 的 `onStart` 到调用结束累计单调时钟时间，排队不计入。单轮超时仍由原执行器停止进程组；停止进程的清理可能略超出计时边界，不会因此补发新调用。
4. 顶层缺口、机制缺口、合并冲突、空结果和超时检查点都不自动视为完整研究。预算或轮次耗尽后，任务停止并保留材料，不自动调用改编。用户可以点击已有的“保留研究，只重新生成选题”按钮，显式接受部分研究；新任务标记 `checkpoint.acceptedPartialResearch`，原任务不变。
5. 后续研究能读取本修订已完成研究轮次的材料；改编与断点复制也保留全部有效研究轮次的目录，不再只留下最后一轮。

## 中断与兼容

正常失败或取消保留实际已用执行时间。异常退出时，如果进程启动已记录、结束时间未记录，则保守消耗该次预留预算并标记估算；不计入服务停机时间。不会自动启动 CLI，不承诺从某一次网页搜索精确续跑。

已有 v3 研究没有 `researchProgress` 时按旧版已保存研究复用，不重写原结果或 Skill 快照。修改梗版本会清空研究进度并重新要求确认。工作流仍是 v3，现有 API 路由和导出结构保持兼容；新增字段可出现在 JSON 导出中。

**回滚注意：**旧程序不识别新的部分研究状态。代码回滚后，不要用旧程序继续重试本版产生的未完成任务；保留新数据只读备查，使用升级前的数据备份或隔离的新数据目录。代码 revert 不等于数据恢复。

## 测试与合并门槛

标准环境执行：

```bash
npm ci
npm test
```

不依赖 Ajv 的状态逻辑与执行器测试可单独执行：

```bash
node --test test/research-state.test.mjs test/runner.test.mjs
```

新增调度集成测试使用假的 CLI、临时数据目录和可控时钟，不会访问真实外部服务。原有超时测试按新语义改为：单轮分配预算、超时保存后继续研究、预算耗尽不自动改编。原执行器测试修正 Linux 僵尸进程误判：PID 存在不等于进程仍在运行；执行器生产代码未改。

本次环境无法解析 npm registry，标准 `npm ci` 未完成。调度集成诊断临时用 Python fastjsonschema 校验原 JSON schemas；这不是锁定的 Ajv，不能替代标准 `npm test`。诊断适配器不属于应用代码，不进入仓库或应用依赖。

合并前须在可安装依赖、已登录 Codex 的隔离环境完成全部标准测试，并实际检查：新建任务、第二轮失败后重试、取消、超时检查点、旧任务副本读取/导出，以及真实梗素材研究和改编。保持草稿 PR，不合并主分支、不执行部署。

12 条查询仍是整次研究的指令约束，程序只累计真实查询日志，尚未实现逐次搜索拦截或独立费用硬上限。没有证明本版能提高研究内容质量，需要真实任务对比。
